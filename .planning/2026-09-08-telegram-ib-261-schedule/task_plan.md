## Acceptance Criteria

1. В чате доступна постоянная кнопка клавиатуры Telegram с точной надписью `📅 Расписание ИБ-261`.
2. Нажатие запускает получение расписания группы `ИБ-261` за текущую дату по часовому поясу ВГТУ.
3. После выдачи доступны быстрые действия `Вчера` и `Завтра`, а также календарь или ввод даты для дальнего числа.
4. Ответ содержит настоящий скриншот только области расписания за выбранный день; принадлежность группе и дате подтверждается метаданными той же загрузки.
5. Текст и скриншот относятся к одной группе, одной локальной дате и одной версии полученных данных.
6. Текст содержит дату, день недели, время каждой пары, предмет, аудиторию и преподавателя, если эти поля указаны источником.
7. При делении занятий на подгруппы показываются обе подгруппы с явными пометками.
8. Ответ содержит кликабельную ссылку на источник и время последней успешной проверки с часовым поясом.
9. При отсутствии занятий это явно сообщается, но скриншот и метаданные проверки всё равно прикладываются, если источник доступен.
10. При недоступности источника показывается последний доступный кэш независимо от возраста, но только с заметной маркировкой «ранее полученные данные», исходной датой расписания и точным временем последней успешной проверки.
11. Частично загруженная, рассогласованная или непроверенная выдача не отправляется как актуальная.
12. Реализация не раскрывает токены и не требует ручного редактирования секретов.

## Decisions Made

| Decision | Rationale |
|----------|-----------|
| План ведётся в gated-режиме `planning-with-files` | Не позволяет объявить реализацию завершённой при оставшихся фазах `in_progress`. |
| Скриншот и текст формируются из одного результата загрузки | Исключает смешивание разных дат, групп и версий расписания. |
| Поля преподавателя и аудитории не заполняются догадками | Пользователь просит показывать их только если они указаны. |
| Кэш никогда не маскируется под актуальный ответ | Это прямое требование пользователя и защита от устаревшего расписания. |
| Сначала проверяется штатная расширяемость Hermes | Избегаем хрупкой правки ядра, которую может затереть обновление. |
| Основной запуск — постоянная reply-кнопка Telegram | Выбрано пользователем; её текстовое событие обычно проще и устойчивее произвольного callback hook. |
| Навигация включает `Вчера`, `Завтра` и дальний выбор даты | Выбрано пользователем для быстрых соседних и произвольных дат. |
| Показываются обе подгруппы | Выбрано пользователем; различия должны быть явно подписаны. |
| Кэш не ограничивается по возрасту | Выбрано пользователем; возраст всегда показывается точно и заметно. |
| Telegram UI реализуется user-plugin через `register_platform_handler`, `pre_gateway_dispatch` и `spawn_task` | Это документированные API Hermes v0.21.0; ядро не изменяется. |
| Основная кнопка использует reply keyboard, дальняя дата — валидируемый ввод | Это не требует callback query и сохраняет штатную adapter-level авторизацию Telegram. |
| Получение и скриншот выполняет изолированный worker | Сетевые и браузерные зависимости не загрязняют процесс gateway; результат возвращается как атомарный JSON-контракт. |

## Risks

- Динамическая страница может требовать браузер и ожидание клиентской загрузки.
- Вёрстка или адрес файла расписания могут меняться без предупреждения.
- Текст на скриншоте может быть недостаточно читаемым без точного кадрирования.
- Нативные callback-кнопки могут иметь ограничения в текущей версии Hermes; нужен подтверждённый путь расширения.
- Источник может публиковать расписание файлами, где один лист содержит несколько дат/недель и сложные объединённые ячейки.
